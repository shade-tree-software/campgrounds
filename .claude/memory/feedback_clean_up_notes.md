**Rule (AWH 2026-10-13):** "if you are working on a campground and you are reading or updating the note field, go through it and clean it up ... Rephrase the notes so they look and read cleanly and so they don't look like a diary of cobbled together snippets of data. Don't go out of your way to clean up the notes. Do it only if you are already reading and/or modifying them."

**Why:** sweeps, audits and fixes kept appending to notes (dated lines, bracketed corrections, MINIMUM STAY and CAMPER-REPORTED RATE lines) without revising what was already there, so many notes carry old or contradictory facts and read like a log.

**How to apply:**
- Trigger: only a note I'm already reading or editing for the task at hand. Never a cleanup pass of its own, never a bulk rewrite.
- Rewrite the whole note as one clean description of the campground as it is now. Merge duplicates, drop facts that later lines superseded, and settle contradictions by the newer authoritative source (check it before choosing). Keep the two-space house style between sentences.
- **Drop what a data field already holds** (AWH, same day: "when updating notes, you can remove information that is already captured in the campground's data fields"): price, RV Life rating, hookups, site count, pull-throughs, facilities (showers, laundry, dump, toilets, water, store, Wi-Fi), season dates, min/max stay, booking platform, phone, website. The popup shows those as chips (group notes and `booking.platform` never reach it, but the Campspot or agency link does). Keep what no field holds: setting, amenities outside the vocabulary (pool, boat ramp, trails), rig-age or rig-type rules, caveats, review scores from elsewhere.
- **A field read from the note must not lose its source when its fact leaves the prose.** Re-tag that group's provenance `source` from `note prose` to `note prose (cleaned out of the note YYYY-MM-DD)`, keeping `checked`/`method`. `apply_absent.py` treats only an exact `note prose` as note-owned, so a later `--rescan` or `_unsupported` can't strip a value the cleaned note no longer repeats.
- Keep what the other rules require, as plain sentences rather than appended lines: a closure or other caveat with its date ([[feedback_add_with_caveat_not_withhold]]), a standing minimum (now marked by the `booking.min_stay` chip, so the note need not repeat it; [[feedback-minimum-stay]]), and a camper-reported rate (stays in the note: AWH asked for it there, and nothing in the popup says camper-reported) called camper-reported, with its month ([[feedback-camper-report-rates]]). URLs still go in `website` ([[feedback_urls_in_website_not_notes]]).
- AWH's own signed text (`--AWH`) is firsthand: keep it in AWH's words with the marker ([[feedback-attribute-note-edits]], docs/campground-curation.md). Clean everything around it and sign my rewrite once with `--Claude`, not line by line. This is the default I chose on 2026-10-13 and told AWH; if they say to tidy their text too, update this.
- Land it with `audit/note_scan/clean_notes.py NOTES.json [--apply]` (items `{id, was, note, set?, provenance?}`): it refuses a note that changed since it was read or that would lose an `--AWH` marker, does the provenance re-tag above, and takes `set` for a field fix found while reading. First used on the 25 Campspot re-checks (`audit/price_research/campspot_recheck_notes_2026-10-13.json`).
- A rewritten note changes its hash, so the entry re-queues for the note scan: `extract_fields.py --dump`, read, `apply_absent.py` for groups the entry lacks ([[reference_session_note_scan]]). `--rescan` only matters for a group still sourced exactly `note prose`, and clean_notes.py has re-tagged those.
