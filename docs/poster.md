# Trip Poster (`templates/trips_poster.html`)

Everything below is load-bearing — most of it was found the hard way in print.
**Read this file before changing the poster.**

Print-oriented poster view of all trips (map + photo border), built from the same photo pool as the trips map. **The sheet's layout size is fixed for the life of the page at the physical size chosen by `?size=` (8×10 default; toolbar dropdown offers 11×14 / 16×20 / 18×24 / 24×36 and RELOADS on change — **standard off-the-shelf frame sizes**, so a printed sheet hangs without a custom mat; the old paper sizes are gone and an unknown `?size=` falls back to the default), on screen and on paper; the screen preview is fitted by `transform: scale(var(--poster-scale))`, never by resizing the sheet.** All pixel constants (callout pills/font, marker sizes, strip row percentages) are tuned against an 816px-wide baseline sheet and scale by `SCALE = sheetWidth / 816` at the top of the script — keep any new pixel constant on that convention. 816 is letter width, and letter is no longer an offered size; it stays the design baseline because re-baselining to 768 would resize every tuned constant by 6% for nothing, so "letter" in that file's comments means "the sheet the numbers were tuned on". Large sizes use the 1600px `/view/` photo derivative (the 480px thumb goes soft in ~2in cells) and inject a matching `@page` size (static CSS keeps only the default-size fallback, since `@page` can't read CSS vars). That is load-bearing: everything on the poster is positioned in layout pixels by JS at load time — Leaflet lays tiles/markers against the map div's pixel box, and `placeCallouts()` hard-codes the SVG `viewBox`, every label position and every leader line from `clientWidth/clientHeight` + `latLngToContainerPoint()` — and **none of it re-runs when the page enters print**. The old responsive sheet (viewport-sized on screen, `width: 100%` in print) therefore widened by ~30% underneath geometry computed for the smaller box, so the print came out with the map's tiles short of the right/bottom edges and the callout SVG stranded at its old size in the top-left corner (its `width`/`height` attributes beat the CSS `inset: 0`, so it never stretched). A transform doesn't reflow, so with a fixed sheet the printed layout *is* the screen layout. Don't reintroduce a print-only size, and don't add `invalidateSize`/`placeCallouts` to the resize handler — resize only changes the preview scale now. Also note `print-color-adjust: exact` on `html`: nearly everything that reads as "poster" is a background (cream sheet, the white photo mattes, the map's water backdrop), and browsers strip those from print by default. Design pass (2026-07-27, all sizes + print PDFs visually verified): Playfair Display masthead/footer (self-hosted variable woff2 in `static/vendor/fonts/`, latin subset, no build step); double-rule frame + paper margin (`--sx` = one letter-design px, same ×SCALE convention); stats footer from a server-computed `poster_stats` (always excludes `home_only`, nights via `camping_nights()`); white photo mattes + two 2×2 hero cells in the bottom strip (**dealt from a ranked deck — hand-starred favorites, then photos with people in them (`detect_people.py` face scan; people+curated before people-only), then grid-leading `curated` photos, then anything — and drawn BEFORE any single, because both walk the same pool and the top strip walks it from the front; fill the strips first and the 68px cells eat every favorite. A portrait hero is swapped with a small cell rather than replaced from the deck, so nothing drops off the sheet; aspect is probed client-side off the 480px thumb because the pool deliberately carries no dimensions. Clicking any small cell swaps it into the nearer hero — page-local, never written to the stored favorites**); a **per-cell ✕ that removes one photo and pulls the next in its place** (hover-revealed, heroes included). Removal is a *replacement*, never a hole — the fixed grid is what the whole page's layout math depends on. The dropped photo goes into a page-local `banished` set that `buildPool()` filters out, so a Shuffle or a People-only flip can't hand a rejected photo straight back; a reload is the undo. **Removing a HERO does not just take the deck's next photo**: the deck holds only *undealt* photos, and by then the singles have eaten every favorite the two hero draws didn't take, so refilling from it alone would hand the biggest cell a rank-4 photo while a starred one sat in a 68px cell — the coin flip the ranked deck exists to prevent. It compares the deck's next against the best-ranked photo already on the sheet (`bestSmallCell()`) and promotes the better one, giving its small cell the deck photo. The ✕ lives INSIDE the sheet, so it's hover-hidden (no hover in print) **and** switched off explicitly by `@media print` and a `.exporting` class the PNG export adds — html-to-image clones the sheet with computed styles, and "the pointer happens to be elsewhere" is not a guarantee; a **People-only toggle** (toolbar checkbox, mirrored to `?people=1` via `replaceState` so it survives the size-change reload and is bookmarkable) that restricts the whole sheet — strips AND heroes — to photos the face scan flagged, since without it the `people` rank only reaches the two hero cells while the other 64 walk the pool at random. It filters `POOL` client-side off the flag the pool already carries (instant re-deal, map untouched, exactly like Shuffle) — **everything that deals photos reads `POOL`, never `PHOTOS`**, and `buildPool()` is re-run after a Shuffle because the filtered array is a copy that an in-place shuffle of `PHOTOS` wouldn't reach. The checkbox disables itself when nothing is flagged (an unscanned library would otherwise print a blank sheet); driven-route overlay fetched from `/api/trips/routes` (canvas renderer, own pane at z 350 so lines sit under markers); callouts are boxless italic-serif labels with a paper-colored halo and deliberately faint leaders (dozens converge on the home cluster — at full ink they bury the routes). **Two print-safety invariants for the map, both found the hard way (base map silently blank in large printed PDFs while markers/routes survived): (1) `window.L_DISABLE_3D = true` must be set before leaflet.js loads** — Leaflet's `translate3d` tile positioning promotes the tile pane to a composited layer, and Chromium's print rasterizer drops composited layers past a size cap (at 24×36, all tiles vanished with the tile filter on, a patchwork without it). Plain left/top positioning prints reliably and costs nothing on a map that never pans. **(2) Because no-3d forces integer zoom** (fractional zoom renders via those same composited transforms; letter framed Mexico-to-Hispaniola a full level too loose), **tight fractional framing is rebuilt statically**: the `MAP_M` block computes the fractional zoom the bounds want, sizes the map div larger by `2^(ceil(zf)−zf)` so integer fitBounds lands on `ceil(zf)`, and scales it back down with a plain 2d transform (verified print-safe). In-map ink (markers, route weights) is sized by `MK = SCALE × MAP_M`; the callout SVG sits on the unscaled wrap and divides container points by `MAP_M`. The muted-tile filter is applied per-tile (`.leaflet-tile`), the combination verified in print at all four sizes. **PNG export ("Save PNG", 2026-07-28)** — print shops want image files, not PDFs, so the sheet also exports as a PNG at `EXPORT_DPI` (200; the capture is scaled `EXPORT_DPI/96` because the sheet lays out at 96 CSS px/in). PNG not JPEG (ringing shows on the hairline rules and small callout italics); 200 not 300 because 24×36 at 300 is a 78 MP / ~310 MB canvas that fails on modest hardware, and it is already past what the base map can supply. Uses **`static/vendor/html-to-image.js`** (vendored, MIT) and NOT html2canvas — html2canvas reimplements rendering and silently drops CSS `filter`, which would export the map in loud default OSM orange; html-to-image renders via an SVG `<foreignObject>` so the *browser* paints and the muted-tile filter survives. Three things that path forces: (1) the capture passes `transform: 'none'` + explicit `width`/`height`, so it captures the true fixed sheet rather than the `--poster-scale` preview (verified: output is 1700×2200 at letter regardless of viewport); (2) `cacheBust: false`, or every tile URL gets a query appended and the whole map re-downloads, missing the CORS-clean copies the `crossOrigin` tile layer already cached; (3) **the callout SVG must carry presentation attributes, not just CSS classes** — html-to-image deep-clones any `<svg>` subtree RAW and inlines computed styles only on the `<svg>` root (its `cloneChildren` returns immediately for SVG), so class rules are absent inside the foreignObject and the labels fell back to 16px upright black with `stroke:none` (invisible) leaders. `CALLOUT_ATTRS` + `applyCalloutAttrs()` mirror the `.callout-*` CSS onto each element; presentation attributes lose to the stylesheet in the cascade, so on-screen and print rendering are untouched — **keep the two in step** (both derive from the same 7.5 / 0.55 / 3 × SCALE constants and read the palette from the CSS vars). The street layer also takes **`tileSize: 128, zoomOffset: 1`** (raster mode only — the local/USB path is protomaps vector, which overzooms on its own): raster tiles carry only ~96 dpi of real detail, so next to 200 dpi vector type the map reads as blurry; one-zoom-deeper tiles painted half-size double it to ~192 dpi with no geometry change. Costs 4× the tile requests (380 at 24×36), which is why it is set here and NOT in the shared `tile-layers.js` factory. Measured end to end: letter ~9 s / 5 MB, 24×36 ~3.5 min / 40 MB — the button counts elapsed seconds because a static label reads as a hang. 24×36 print PDF re-verified after the tile change (the blank-base-map failure did not recur).
