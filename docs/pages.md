# Pages: per-template detail

Moved out of CLAUDE.md on 2026-10-25 to keep that file small. Treat this as part of the project instructions: read it before touching the code it describes.

The one-line summaries stay in CLAUDE.md's Templates list; this holds the rules behind them.

## `templates/base.html`

- `templates/base.html` — Sticky header+nav in `.site-top`. Publishes `--site-top-height` for child pages' sticky sub-headers. Nav groups: Trips (Map, Calendar, List, Stats), Campgrounds (Map, Availability — both hidden from Trips-only users; Weather — contributors only; Manage — admin-only), Admin (Users, Access Log — admin-only). Header shows combined trip (overnight + day) / nights counts (hidden ≤700px); `inject_trip_stats` still publishes `overnight_count`/`daytrip_count` for anything wanting the breakdown. On phones a fixed bottom tab bar (Map/Calendar/List/Stats/Camps — Camps hidden from Trips-only users) is primary nav, publishing `--tab-bar-height` which viewport-height map calcs subtract. Also defines `window.toast(message, kind, opts)` (non-blocking notifications; `opts.actionLabel`/`onAction` for undo-style toasts — used instead of `alert()` app-wide; `confirm()` stays for destructive actions), hover-prefetch for links, and service-worker registration. **Hover-prefetch skips `/campgrounds/map`** (it embeds the whole database, so it's megabytes even gzipped — speculatively pulling that because a cursor drifted across the nav link costs far more than the round trip it saves) **and is disabled entirely under `Save-Data` or a 2g/3g `effectiveType`.**

## `templates/trips_map.html` (landing page)

- `templates/trips_map.html` — Photo filmstrip slideshow + Leaflet map of all locations. Clicking a filmstrip photo opens the shared lightbox (full-size original, its caption, arrow/swipe paging across the other on-screen slots, and a card linking through to that photo's trip — trip name + date, the name of the campspot/event/waypoint the photo sits under, and an "Open trip ›" pill) rather than navigating away; the slot stays a real `<a href="/trips/N">` so ctrl/cmd/middle-click and "open in new tab" still go straight to the trip. Rotation pauses while the lightbox is open. Family-marker popups list the union of trips that stayed at that location (coord match) and trips that contain a family-visit event there (`family_id` match), deduped and sorted by trip start. Also draws every trip's **GPS route line** (see `docs/gps-track.md`) as a toggleable overlay. A navy **"All N Trips" pill** floats over the map's top-left (N is `inject_trip_stats`' `trip_count`, the same var the site header uses); it is a `<button>` that re-runs the page's own `fitAllTrips()` — the only way back to the opening framing now that the zoom control is gone — and disables itself when there are no bounds to fit. Its text is aligned to the banner cards' labels below it (their 6px accent border + 1rem padding = 22px), so the two read as one column.

## `templates/campground_map.html`

- `templates/campground_map.html` — Color-coded by proximity-to-water or climate. Family entries are excluded from the campground dots/legend but rendered as red house markers (like home), same as the trips maps — fed by `family_locations` from `_map_config()`. **Filters (AWH 2026-10-26): three pieces with one job each** — the bottom-left **legend** explains the colours (Color-by picker, one clickable row per category, "Showing N of M · F faded"); a **quick-filter row** along the very top of the map, above the search box, holds the Filters button (badge = how many filter groups are set, defaults excluded) and four one-tap chips (`$50 or less`, `Electric`, `On the water`, `4★ and up`), each showing the setting actually in force when on; `layoutTopControls()` keeps the layer control's icon in the top-right corner while the row leaves room for it and otherwise drops it below the row, level with the search box (`body.cg-layers-down`, which also narrows the phone search to make room), giving the row the whole width; a row still too wide scrolls sideways, with a chevron over each edge that has chips scrolled out of view (AWH 2026-10-26); the **Filters panel** (a sibling of the map div, outside Leaflet, so nothing in it reaches the map; right-side panel on a desktop, bottom sheet ≤ 700 px) holds every filter in sections — Price (Nightly rate + RV Life `$`), Rating, Hookups, Proximity to water, Climate, Ownership, Status, Missing data — with Clear all and "Show N campgrounds". Every control mutates the shared state and calls `filtersChanged()` → `applyVisibility()` → `syncFilterUi()`, which re-syncs all three, so they can't disagree. Water and climate categories are ONE `hiddenCategories` set filtered per field (`waterCat` / `climateCat`), not per colour mode, so a water filter survives switching to climate colours. The old bottom-right Filters box is gone; the scale bar holds that corner. The panel filters by `ownership`, built from `OWNERSHIP_LABELS`; **`wma` and `hipcamp` start unchecked** (`DEFAULT_HIDDEN_OWNERSHIPS`) — informal wildlife-area camping and a booking platform are both narrower answers than "where can we camp", so they're opt-in. That seeds only the sessionStorage FALLBACK, so a session that switches either on keeps it on, and Clear all returns to it. The structured filters are the **rating filter** (minimum stars / maximum `$` tier), since 2026-09-18 a **Hookups** select (Any / Electric / Electric + water / Full), and since 2026-10-26 a **Nightly rate** cap (Any / $50 / $30 / $20 / Free; Canadian rates at C$69 = US$50) — see doc §8.5. Rating was the one structured-schema filter the data could support when it shipped — `rating.stars` and `rating.price_tier` are on 76% and 90% of entries, against 0% for hookups/facilities/season at the time, and everything populated in booking/fees was inherited from the policy registry, which doc §3 forbids being the sole reason to exclude an entry. Phase 3 then filled `hookups` from note prose (electric 58% / water 67% / sewer 57%, none inherited), which is what made the hookups filter possible; **re-measure coverage before choosing the next one**. **The rating pair, three hookup booleans and the base `rate` (+ `cad`) are the only schema fields in the inline marker payload** (`_MAP_RATING_FIELDS` + `_MAP_HOOKUP_FIELDS` + `fees.nightly_low`, doc §8.4's client-side-filter exception, measured at +20 KB, +16.5 KB and +21 KB gzipped); everything else rides in the per-id popup fetch. **An entry an active filter can't evaluate is faded, never dropped** (doc §2.2) — `fillOpacity` 0.25, since the fill color is already spoken for by the legend — and ONE "include unknown" checkbox shared by every structured filter, on by default and worded for whichever filters are set ("Include unrated" / "Include unknown hookups" / "Include unpriced" / "Include unknown"), is the only way to hide them. A hookup recorded as absent hides an entry, and so does a measured rating failure; an unknown on one filter never rescues a failure on the other (`schemaPasses` / `schemaUnknown`). Under Full hookups about half the map fades: that is the real state of the data, not a bug. A naive `stars >= 4` would silently lose 3,006 campgrounds, 24% of the database and mostly the public land RV Life never rated. Both counts in the panel come from the render pass, not a second walk over `CAMPGROUNDS`, so the note can't describe a different map than the one drawn. More bottom-corner boxes stay rejected: each costs a phone ~90px even collapsed, and the mobile rule lifting bottom controls clear of the attribution applies to each of them. New filters go in the panel. `tests/test_rating_filter.py` pins the §2.2 rules for both filters by running the template's own predicates in quickjs against the real data (quickjs won't load from the noexec scratchpad; `pip install --target ~/.cache/ekko-jslib quickjs` and run with that on `PYTHONPATH`). Popups show name/state/elevation/visit-count/note/phone/websites + admin-only edit link (a website link is labelled by its domain; when two links share a domain each is followed by what its path names — "fs.usda.gov · Mower Basin Trail Map (PDF)" — via `sfLinkLabels` in `static/campground-schema.js`, pinned by `tests/test_link_labels.py`) to `?edit=<id>` on the manage page. Below that, the structured fields (`docs/campground-schema.md`) are drawn as one run of rows: in each, what was verified for THIS campground first, then — in the manage form's muted tan with an asterisk, and only when the server could name the agency — what it merely inherits, explained by one footnote ("* Typical for Indiana state parks — not checked for this campground"). They used to be a separate "Typical for" section with its own layout; AWH 2026-10-09 rolled them into the rows (doc §8.6). All chips are phrased by the shared `static/campground-schema.js`, and the values ride in the per-id popup fetch rather than the inline marker payload (doc §8.4); only the ~5.8 KB of field metadata is on the page. **Temporarily closed campgrounds** (`status.operating == "temporarily_closed"`, schema doc §4.5) draw grey with a dark rim instead of their legend color — every fill goes through `markerFill(cg)` so a color-mode switch or inline edit can't repaint them — the popup leads with a red "Temporarily closed · expected to reopen …" line, and a "Show temporarily closed" checkbox in the Filters panel (on by default, AWH 2026-09-30) hides them; the marker carries `closed`/`reopens` only when closed. `tests/test_closures.py` pins it. A 🚗 route tool (top-left, under the locate control) lets any user click two points — empty map or a home/family/campground marker — to draw a driving route between them via the public OSRM demo server (`router.project-osrm.org`, browser-side fetch, CORS-open, no key, so it's independent of the Flask host's outbound whitelist); the route is a blue polyline with a bottom-center status pill showing distance + drive time and a Clear button.

## `templates/trips_photos.html`

- `templates/trips_photos.html` — The whole photo library in one gallery: search, year filter, favorites filter, sort, grouped by trip, paged 60 at a time. **Every control is a query param** (`q` / `year` / `favorites` / `sort` / `page`), so a filtered view is bookmarkable and shareable, Back undoes a filter, and paging can't silently drop one — `photos_href(**over)` in the route builds every link by carrying the current controls forward and is the reason no link can forget one (it deliberately omits `page`, so changing a filter lands back on page 1 rather than on a page number that may not exist in the new result set). Filtering is server-side because the library is thousands of photos and only 60 are ever in the DOM. Search covers trip name, campspot/event place, state, caption and year, ANDed across terms, and matches on **word prefixes, not raw substrings** — "acad" finds Acadia, but a two-letter state code like "ME" must not match the middle of "Home" (`_search_haystack` / `_search_terms` normalize both sides to space-delimited words so the test stays a plain `in`). Photos are grouped into per-trip sections with a header sticky under `--site-top-height`; the lightbox is still opened with the whole page as its set (`openPagePhoto`) so arrows page across group boundaries. Within a trip, photos run in **the trip's own `timeline` order** (`_timeline_positions`) — campspots and events interleaved by date, which is the app's single definition of what happened when. Ordering them campspots-then-events looks right until you meet a real trip: trip 92 is 6 campspots and 33 events over 8 days, so that grouping put day-8 photos above day-1 ones. A campspot split across nights takes its FIRST timeline slot, so its photos stay in one run instead of scattering. Inside a card, photos follow `photo_seq` — the same display order the trip page uses (`_display_order`: explicit `photo_order` drag order, then the rest alphabetically), so the gallery can't disagree with the page a photo lives on. Sorting is never reversed *within* a trip: "newest first" is about which trip you see first, not about reading a trip backwards. `_photo_card_order` survives only as the fallback for a card the timeline doesn't mention (photos orphaned by a deleted campspot); it parses the index numerically because `"stay-10"` sorts before `"stay-2"` as a string.
  - **`_photo_gallery_index()` is cached against the pool object it was built from.** Enriching every photo with trip name/place/year/haystack costs ~50 µs each (238 ms for 5,000, measured), and that answer only changes when a photo or trip does. Keying on `_collect_photo_pool()`'s identity means it rebuilds exactly when the pool does — on that 60 s TTL or an explicit invalidation — so it inherits the same freshness contract as the landing slideshow and poster, including trip/campground renames (which reach this page only via `parse_trips()`). Measured at 5,000 photos: 36 ms warm, 24 ms filtered.

## Weather Finder: `weather_finder.py` and `templates/weather_finder.html`

- `weather_finder.py` — Forecast search engine behind the Weather Finder page and the `find_summer.py` CLI. Stdlib-only (no `requests`/`geopy`). Batches Open-Meteo forecast requests (comma-separated coordinate lists, one object per location), snaps coordinates to a ~11 km grid so campgrounds sharing a model cell share one fetch, and caches per-cell forecasts for an hour. **The cache is what makes the page usable:** Open-Meteo's free tier bills per LOCATION and allows 600/minute (measured: 600 OK, 800 → 429), so a 400-mile search (1,289 campgrounds) spends most of a minute's budget — without the cache, adjusting a threshold and re-searching would rate-limit almost every time. Cached cells don't compete for `FORECAST_BUDGET`, so an over-budget radius fills in across successive searches rather than being permanently clipped to the same points.
- `templates/weather_finder.html` — Contributor-only Weather Finder page (admins + `can_upload` users, via `_require_contributor_page()`; the Campgrounds-section gate runs first, so a Trips-only contributor is bounced too). It's a trip-*planning* tool and each search spends a real slice of the forecast provider's per-minute budget, which is why it stays with the people who plan the trips rather than every reader. Three modes (comfort range / cooler than home / warmer than home), optional rain and waterfront-only filters, weekends-only, an origin other than home via `/api/geocode`, and four sort orders (distance / temperature / rain / waterfront type). A separate by-name lookup panel sits **outside** `.wx-form` on purpose: it ignores every control in the form (distance, mode, filters), and nesting it would imply otherwise. **Sorting re-runs the search** rather than reordering the page: results are capped server-side, so reordering the returned page would sort the 200 *nearest* by rain instead of showing the 200 driest. Waterfront ranks by tier, not alphabetically — water's-edge types, then `coastal woods` (an earned on-water designation but no sightline, which is why the map's On-the-water filter excludes it), then view-only, then none. Results are grouped one card per campground with a chip per matching day — never one row per campground-day, which for a wide search is tens of thousands of rows. Every chip shows rainfall even when the dry filter is off, because "82°F and 1.1in of rain" is a different trip from "82°F and dry". **A forecast map sits above the list** (2026-10-07), showing every campground the search CHECKED — misses included, because shading only says "it's cooler to the north-west" with the whole region in it — while the list stays capped and matches-only. It rides on the search response as `map` (`_map_payload` in `weather_finder.py`): weather once per forecast cell as rows aligned to one shared `dates` list, campgrounds as short rows pointing at their cell (~4× smaller than per-date dicts; ~275 KB raw for a 400-mile, 16-day search). Shade by **temperature** (diverging blue–grey–red: range mode colours the actual high centred on the comfort band, which is marked on the legend; relative modes colour the difference from home, centred on 0; the half-span is fixed per search, never stretched to the data, so a mild region doesn't read as a dramatic gradient) or **rain** (sequential one-hue blue, square-root spaced to 1"/day). A day select picks one day or the window AVERAGE (mean, not best — the map is a picture of the weather, not a ranking). Match vs miss is carried by dot size and a dark ring, never colour, so it doesn't compete with the shading; dots grow with zoom (`markerSize`) because a thousand full-size dots at continental framing merge into a mat of outlines. Popups reuse `dayChip()` and link to the result card when it is on the page. Reframes only when origin/radius changes, so a re-sort keeps your zoom. Touch-primary devices get `dragging: false` (one finger scrolls the page, two pinch the map).

## Roadside stops: `roadside.json`

- `roadside.json` — Leg-stretch stops (small-town parks, roadside picnic areas, rest areas) — deliberately separate from overnight campgrounds. Rendered as their own toggleable overlay on the campground map, with admin CRUD inline on that map (no dedicated manage page). `_roadside_view()` projects the stored record into the map shape. An optional `visitor_center: true` marks the stops that double as a **staffed travel-information point** — state/DOT welcome centers, travel & tourist info centers, park visitor centers (AWH 2026-08-14: lean hard on that category). **A museum qualifies only if it is FREE *and* hands out travel info**; a paid-admission museum never counts, however good it is — the flag means "you can stop here and get oriented for the road ahead," not "there's an attraction here." **National/state park visitor centers behind an entrance fee are the one exception** (AWH 2026-08-14) — they're the place you plan the park from, and a park you've already decided to visit isn't an admission charge you're weighing. **The price of that exception is that the `note` must SAY so**, naming the fee and any reservation system (RMNP's Alpine and Moraine Park Discovery centers carry the entrance fee plus timed entry, and Bear Lake Road's window is tighter still), so the flag never promises a free walk-in it can't deliver. Prefer the free ones where a park has both: Beaver Meadows, Fall River and Kawuneeche all sit *outside* their entrance stations. Applied default-down like the campground evidence gate, so the ones that don't make it are as instructive as the ones that do: Cracker Trail Museum at Pioneer Park ($3 admission), Tyrone History Museum and the J.C. Penney Museum (both free but no travel-info role found), a park building merely *named* "welcome center" that is really restrooms + ADA amenities (Tripton Park), a turnpike plaza whose chain's actual staffed welcome desk is at a different plaza (Lawn), and an interpretive trail with no facilities (Fleetwood Hill). Fort Necessity NB stays in because its NPS visitor center is free to enter. Those that qualify draw a blue ℹ marker instead of the green picnic table and are prefixed ℹ️ in the search dropdown, the nearest-stops list and the near-the-route panel. **The key is stored only when true** (create/update pop it when the modal's checkbox is cleared), so absent == an ordinary stretch-break stop; `_roadside_view()` normalizes it to a real bool for the template. Visitor centers stay inside the one roadside overlay — they're a marker distinction, not a separate layer.
