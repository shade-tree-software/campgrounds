# Day rollups (`process_rollups.py`)

Moved out of CLAUDE.md on 2026-09-19 when that file passed the 150 KB loader limit. Treat this as part of the project instructions: read it before touching `process_rollups.py`, `audit_rollup_figures.py`, `trip_data/day_rollups.json`, or the dossier/prompt rules. The display side (typed day notes outrank drafts) is in CLAUDE.md under "The Day's Write-Up".

`process_rollups.py` drafts a short write-up per trip-day from a **dossier** of facts (`day_dossier()`), via `claude-opus-5`. **The prompt and the dossier both target the SHORT form** (25-45 words, impersonal voice, the shape of the day) — rewritten 2026-09-11 after the long rollups were rejected. **The few-shot examples are the family's OWN `day_notes`, chosen per day at run time** (`build_example_bank` / `choose_examples`) — see "Examples come from the day notes" below; four hand-picked trip-95 summaries used to sit frozen in `SYSTEM` and no longer do. **The dossier's refusals are the design:** it carries no stop names, descriptions, captions, campground names, site numbers or photo counts, because every one of those is printed on the cards directly below the write-up and a model handed a list of places will name them — no prompt rule survives contact with the data. What it does carry is what a reader scrolling the cards can't assemble: real mileage and driving time (the old `_drive_bucket` said "very long", so it could never have produced the approved "520 miles and nine hours at the wheel"), `heading`, `states`, the ending elevation, and `trip_miles_by_day` so a day can be placed in its trip ("the biggest driving day"). **ABSENT IS NOT ZERO, and this shipped wrong once.** `_trip_driving_by_day` OMITS a day rather than reporting "0 mi", so a day with no GPS had no `miles` key — and the model read the silence as a measured zero, writing "the trip opened parked" for a day that drove from home and "a second day without driving" for one that moved between two campgrounds. Three of the library's four track-less days were wrong. The dossier now separates the three cases outright: a figure; `driving: negligible` (measured, under `DRIVE_DAY_MIN_M`, genuinely stayed put); or `mileage: not recorded` plus `moved`, which `_day_moved()` reads off the BEDS (waking and sleeping in different places, or having only one of the two) because that is knowable without a track. **The same trap bit a second time one fix later** in `trip_miles_by_day`, where an unrecorded day rendered as `0` and read as a pause — it is `None`/null now. The prompt says both out loud (don't cite rule numbers — they move); `tests/test_day_dossier.py::TestAbsentMileageIsNotZero` pins them. **`states_crossed()` is the one fact that was nowhere in the trip record** — a day's stops name only the states it STOPPED in, dropping every state it merely drove across (trip 95's 2026-08-20 stopped in MD/PA/IN and also crossed WV and the whole width of OH). Read off the GPS with the offline `nearest_town` gazetteer, ~40 sampled lookups per day, no API call and works on the USB build; a host without the gazetteer just loses the field. Near a border the nearest town's state can be wrong — accepted, since the alternative is a polygon set the repo doesn't carry. Writes `trip_data/day_rollups.json`. **Start with `--dry-run`**: it prints the dossiers and costs nothing, and the dossier is the half with a right answer — garbage in is confabulation out. Key rules: a day **nobody wrote a word about still gets an entry** from facts alone (captions and notes improve a day, they don't gate it — which is what lets all 321 back-catalogue days be covered); a **hand-edited rollup survives `--force`** (`--force-edited` is the override), every rollup is stamped with the model that wrote it, so a generated sentence is never mistaken for one of yours. **A stop earns a mention exactly as it earns a timeline card** — photos or a description — and the rest collapse into a nameless `unremarkable_stops` count; without that the dossier for a travel day is Amoco, I-70 West Rest Area and South Vienna Rest Area, and the model writes a paragraph about buying fuel. Keeping the two tests identical also stops a rollup describing something the timeline above it has folded away. `tests/test_day_dossier.py` pins the dossier and `tests/test_rollup_examples.py` the example selection; the prose is a judgement call and has no test. **The whole library (327 days) was redrafted by hand in conversation on 2026-09-13** after the rules below changed, and 92 of those entries were rewritten again the same day for the bare-"Away" rule — mean 16.3 words. **PA holds the authoritative copy** (uploaded 2026-09-13), which is what `sync-from-pa.sh` expects — it stopped excluding this file on 2026-09-11 precisely so the drafts come home that way. A local redraft is therefore only half done until it is pushed up to PA; otherwise the next sync pulls the old text back over it. **A typed day note outranks whatever this writes** (see "The Day's Write-Up" in CLAUDE.md) — the generated draft is the fallback for a day nobody wrote about, not the primary.

- **Examples come from the day notes, and that is the whole feedback loop** (2026-09-13). Every hand-written `day_notes` entry is paired with the dossier its day would be drafted from, and the four closest in SHAPE — round-trip vs travel, mileage band by RATIO, first/last day, event count, family visit — ride in the user message ahead of the day's own facts. A note is nearly always a day where the draft was read and found wanting, so the pair (facts, what they actually wrote) is the best training signal in the repo, and it grows every time a note is typed: **writing a note is now how you correct the drafter**, with no prompt edit and no redraft of anything else. Notes must be read with `trips.get_day_notes()` — `parse_trips()` does NOT carry the field. The bank is built from the WHOLE library even under `--trip`, because one trip rarely holds four days shaped like the one being written; capped at two days per trip so one trip's voice doesn't become the only voice; and the examples' `trip_outline` is dropped (longest field, least transferable). They ride in the USER message, never in `SYSTEM`, which is cached across the run. `--no-examples` turns it off.
- **The eight rules the 2026-09-13 pass added all came from diffing 39 notes against the drafts they replaced** — that is what the notes are FOR, as data. In order of how often they bit: prefer driving TIME under ~130 miles and MILEAGE over ~300 (every figure ≥131 mi survived the rewrite; 62/66/81/89/107/122/123 were all cut or replaced by a duration — AWH 2026-09-13: "I tend to prefer timespans for short drives and mileage for long drives"); tell the day in CLOCK order, since an event before `left_at` is the morning at the place the day started and putting the drive first tells it backwards (and dropping that event entirely, which happened, loses how the day began); anchor each name to its part of the day; `states` is an ORDERED CROSSING, so `["SC","GA"]` is "through South Carolina and into Georgia", not "through Georgia"; place the day at most ONCE and only with something countable (the longest driving day, the third of four ~400-mile days, the highest point — never "the trip turns here from family visit to touring", "the arrival day", "the only day that stayed put"); a first day leaving after ~16:30 on a weekday left **after work**, which AWH added to 4 of 4 such days; 35 words is now the hard ceiling, because the added rules made the drafts longer than the notes they were meant to match. **A ninth rule came the same way and is about the drafter's own tic:** never open with a bare "Away" — `Away <time of day> and <N> miles <direction>` opened **84 of 327** entries, so every day it fronted read as the same day. Of the 10 days where AWH wrote a note over an "Away" draft he kept the word twice, and both keepers hang something concrete off it ("Away mid-morning under light snow", "Away from Erie and 174 miles southeast" — prepositional, not the bare adverb). The four things he does instead are all in the prompt: let the DIRECTION be the verb and drop the departure entirely ("Northeast 188 miles to the Svendsens'" — his note over a draft that ended "away after midday"), name the drive as a thing ("an evening drive after work", "a 24-mile hop", "the last leg"), use a phrase with a body in it ("back on the road", "headed out", "on to home"), or put the morning first and reach the drive with "then". **When the morning held nothing, the direction and the distance are the whole opening.** **Voice stays impersonal** even though 5 of the 39 notes use "we" — the notes are the human channel and the draft has to stay visibly a different kind of text (AWH 2026-09-13).
- **A tenth rule: the figure is the WHOLE DAY's drive, bed to bed, and must never be hung on the stretch after a named stop.** "Church at Grace Anglican in the morning, then 160 miles east for home" (trip 77, 2025-11-09) reads as a 160-mile run from the church; the church was 101 miles into a 160-mile day and only 59 came after it. The number was right and the sentence was false, which is the failure mode a reader can't check — **every one of the library's 156 mileage figures matches a real measurement**, so nothing is ever invented; only the placement goes wrong. It bit whenever the day drove a long way BEFORE the first thing the entry names, which is rare (the named stop is usually the morning at the campground it woke in) — 2 of 327 entries, the other being trip 58's 2025-05-23, where the record's bed-to-bed leg said 234 mi for a day the GPS shows driving 423 out and back from home. Fix a day like that by dropping the figure, not by printing the bigger one: the trip page's day divider prints the same leg, and the two must not contradict.
- **`audit_rollup_figures.py` re-runs all of that against the GPS** — figures that match no measurement, figures hung on the wrong leg, and durations matching neither driving time nor elapsed span. Read-only, non-zero exit on a finding. Two traps it cost to learn, both of which made an earlier version silently useless: a matcher must accept a PARAPHRASED name (the entry says "Grace Anglican" where the record says "Grace Anglican Church", so match every contiguous sub-phrase) and must never match placing/generic words (an early version anchored "336 miles" on an evening *Lake Rowena Park* waypoint because "park" appeared in "Memorial Park", and flagged every entry opening with a heading because "south" matched "South Seagrove Welcome Center"); and **"at the wheel" / "on the road" are DRIVING idioms that look exactly like dwell-time phrases** ("an hour at George Washington Memorial Park"), so a dwell filter that doesn't except them blinds the duration check on the very entries that name a driving duration. Self-test by injecting each of the three shapes before trusting a clean run.
- **Terrain is allowed only where the dossier MEASURES it** (AWH 2026-09-13, on the corridors he kept adding by hand — "through the Blue Ridge and into the Massanutten Valley", "climbing US-34"). Four fields and nothing else: `to.elevation_ft`, `high_point_ft`, `to.waterfront`/`to.water`, `to.within` — at most one per entry, and only when it says what the campground's own name doesn't. The ban on the rest holds because **the model was already inventing geography and getting away with it**: "Elizabeth Furnace on Passage Creek" was right and came from nowhere in the record. `campground_context()` reads the water and the park off the entry's own note, precision-first (the phrase must be capitalised words ending in a feature type inside ONE clause — without that bound "…Boundary Campground. USFS Cherokee National Forest" parses as one name), so ~19% of the database yields something and the rest is honestly silent; `waterfront` itself is audited on every entry and carries the rest. `day_high_point_ft()` samples the track evenly BY DISTANCE (ping density is highest where the day stopped moving) and asks the Open-Meteo DEM — the same DEM every campground was pinned against — withholding the answer unless it clears both beds by `HIGH_POINT_MIN_GAIN_FT`. It exists because a day spent on Trail Ridge Road near 12,000 ft was written up as "based at Moraine Park at 8,200 feet". Answers are cached in `trip_data/day_elevation_cache.json` (gitignored) and the free tier meters LOCATIONS (600/min), so a back-catalogue run walks into a 429 and waits once; `--no-elevation` skips it on an offline host.
- **The clock and the compass were both wrong on the days that touch home, and both fixes are anchors** (2026-09-13). `day_clock()` now takes the BEDS (`day_anchors`: home.json on the first and last day, the covering stay otherwise) instead of the day's first and last PING. OwnTracks suspends reporting while a device sits still, so the first ping of a day that started at home is routinely already miles away — on trip 90's 2026-06-05 it was the drive to work, the departure circle formed around the office, and the dossier reported "left 07:10, arrived 21:11" for a trip that left at 18:54 and drove two hours. The draft said "fourteen hours between leaving and arriving" and was the most heavily rewritten entry in the library. Same anchors fix `heading`, which needs a stay at BOTH ends and so was absent on every leave-home and return-home day, leaving the model to guess from the state list: all three compass corrections AWH made were those days (north→northwest, south→southeast twice).
- **Two rules decide when a day is drafted, and together they are what makes an unattended run safe to schedule.** (1) *Only when its facts moved:* each entry stores `inputs_sig`, a hash of the narrow set a summary is actually built from — the day's driving and the campspots bounding it (`day_signature`). A trip gathers hundreds of edits during it and for weeks after (photos, captions, descriptions, waypoints, notes, reordering) and **none of them are inputs**, so a nightly run over the library normally drafts nothing and costs nothing; when mileage or a campspot really changes, that day alone is redrafted. **Do NOT reuse `_trip_route_signature`** — it hashes the whole raw trip record, which is right for a route and exactly wrong here. **A record with no `inputs_sig` is legacy, not stale** (read the other way, the first run after this shipped would redraft everything); those are stamped free, with no API call. If the dossier is ever widened toward captions/descriptions, widen `day_signature` with it or the drafter will never notice they changed. (2) *Only once its GPS settled:* an in-progress trip re-polls the tail of its track, so a day inside that window can still gain distance and be written up as "312 miles" when it ends at 400. `day_settled` measures from the END of the day, not the trip's, so one rule covers both a finished trip and a running one whose older days are ready; the window is read off the app's `TRACK_REFETCH_OVERLAP_S` rather than copied. `--ignore-settle` overrides. **Nothing is immune to being redrafted** (AWH 2026-09-11). `source: "conversation"` briefly outranked `--force`, but a hand-written summary is LLM text either way and freezing it costs a library that cannot respond to its own facts being corrected — promote a waypoint to an event or fix a campspot date and the day that should change keeps its old prose forever. `source` records provenance, not immunity. The human channel is `day_notes`, which needs no protection because it outranks every rollup at display time; `edited` is vestigial, since the app writes a note OVER a draft rather than editing it. `tests/test_rollup_scheduling.py` pins both rules.
